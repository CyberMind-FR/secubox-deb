# Pilotage L1 « Voir » — arbitrages et mineurs reportés (#3126)

Relevé du registre d'exécution de `2026-10-28-pilotage-l1-voir.md`, au 2026-10-29. Chaque arbitrage dit ce qui a été décidé, pourquoi, et ce que cela coûte si c'est faux. Les livraisons L2 « Agir » et L5 « interface headless » partent de ces décisions ; R40 liste ce que la tâche 1 de L2 doit reprendre.

## Arbitrages

- ## Rulings pré-vol
- Ruling R1: `Device.DeviceInfo.SoftwareVersion` est rendu par la source paquets (T2), pas par la source système (T1) — une seule source par chemin évite deux valeurs concurrentes — coût si faux : déplacer un chemin d'une source à l'autre.
- Ruling R2: T1 ajoute `func Aplatir(res []Resultat) map[string]any` (chemin complet → valeur) dans `internal/modele` ; T3 `Observer` consomme cette table — l'interface de T3 suppose une table plate que T1 ne fournissait pas — coût si faux : une fonction utilitaire de plus.
- Ruling R3: T8 définit le contrat minimal de stockage qu'il consomme (`class StockageCanal(Protocol)` : `vu(box: Box, infos: dict) -> None`, `notification(box: Box, evenement: dict) -> None`, `resultat(box: Box, msg_id: str, reponse: dict) -> None`) avec une implémentation mémoire pour ses tests ; T9 implémente la version SQLite conforme à ce protocole — T8 précède T9 dans le plan — coût si faux : ajuster les signatures en T9.
- Ruling R4: toute Source des tâches suivantes implémente l'interface facultative `Declarant` (sinon ses chemins disparaissent de GetSupportedDM) — relevé par la relecture de T1 — coût si faux : une source absente de Supportes, rattrapable
- Ruling R5: I4 (lanceur systemctl réel : exec.CommandContext + WaitDelay, processus tué au délai, test sur faux exécutable) devient un critère d'acceptation de la Task 6 (câblage de main) — le lanceur de production n'existe pas en T2 — coût si faux : goroutines/processus accumulés si T6 l'oublie
- Ruling R6: `releve.Releve` sans balises JSON → l adaptateur `operer` de la Task 6 sérialise en snake_case (duree_s, cpu_pct, …) ; pas de reprise de T4 — l adaptateur est le seul point qui produit `output` — coût si faux : noms de champs à renommer côté maître
- Ruling R7: formats de corps de T5 font foi pour T8/T9 : GET_RESP `{"results":[{"path","params","err"}],"tronque"?}`, GET_SUPPORTED_DM_RESP `{"paths"}`, OPERATE_RESP `{"output"}`, POST /reponses en lots ≤ 256 Kio — reportés dans les briefs T8/T9 — coût si faux : ajuster le parseur du maître
- Ruling R8: l adaptateur `operer` de la Task 6 doit respecter ctx (sinon l arrêt de l agent traîne jusqu à 300 s pendant un relevé) — relevé par la re-relecture de T5 — coût si faux : arrêt lent
- Ruling R10: `AF_NETLINK` ajouté à RestrictAddressFamilies de l unité (le brief ne listait que AF_INET AF_UNIX) — `net.Interfaces()` de Go passe par netlink ; sans lui, découverte du maître et source maillage échouent — coût si faux : une famille d adresses de plus (lecture seule des interfaces)
- Ruling R11: le profil AppArmor autorise `bind` (sans listen/accept) — le canal lie sa source à l adresse du tunnel (D1) — coût si faux : aucun port d écoute possible de toute façon (pas de listen)
- Ruling R12: le fichier d environnement /etc/secubox/pilotage-agent.env peut être déposé par le compte partagé `secubox` (/etc/secubox en 0755 secubox) et rediriger l agent vers un faux maître local — accepté en L1 (lecture seule) ; AVANT L2 (actions), l agent refusera un fichier d env qui n est pas root:root et non inscriptible par d autres, et le plan L2 portera ce contrôle — coût si faux : un faux maître local lit l inventaire en L1
- Ruling R13: la projection va dans un dossier root `/var/lib/secubox/autoload-public/` (0755 root:root, créé par autoloadctl par descripteur sous /var/lib/secubox), fichier `pairs-publics.json` 0644 — ajouter secubox-pilotage au groupe du service lui ouvrirait aussi la base (jetons, clés) ; T8 lit ce chemin — coût si faux : un chemin à changer côté maître
- Ruling R14: l abonnement projeté est le même état calculé que `lister` (l admin et le maître voient la même chose), « echu » devient une 4e valeur permise — coût si faux : une valeur de plus à afficher en T11
- Ruling R15: files et stockage indexés par la clé `Box.cle = "<reseau>:<nom>"`, pas par `nom` seul — un nom de maillage égal à une série Auto-Load partagerait la file (cloisonnement) — coût si faux : une propriété de plus
- Ruling R16: Task 10 : nginx pose `proxy_set_header X-Real-IP $remote_addr;` (écrase l en-tête client) devant la socket du canal, et rien d autre n identifie une box — coût si faux : usurpation d identité par en-tête
- Ruling R17: Task 9 : méthodes de StockageCanal synchrones, appelées par asyncio.to_thread → connexion SQLite courte par appel (ou une par thread), WAL — coût si faux : « database is locked » / objets SQLite partagés entre threads
- Ruling R18: identité fermée par défaut sur toute ambiguïté — une adresse présente avec des entrées divergentes, ou une clé (réseau:nom) portée par plusieurs adresses → aucune de ces box n est identifiée, une ligne de journal par table rechargée — l adresse WireGuard authentifie, le nom n est qu une étiquette ; mieux vaut une box non pilotée qu une file partagée — coût si faux : deux MOCHAbin au nom par défaut non pilotables tant qu on ne les renomme pas
- Ruling R19: en L1, l identité maillage ne retient de peers.json que les entrées enrôlées (portant `fingerprint` ET `joined_via`) ; une projection publique (nom, mesh_ip) écrite par p2p sur le modèle de R13 est un préalable de L2 (#3253) — peers.json est aussi alimenté par mDNS non authentifié — coût si faux : une box enrôlée à l ancienne sans ces champs non pilotable
- Ruling R16 (complété) : socket `/run/secubox/pilotage-canal.sock` en 0660, groupe de nginx (www-data), jamais 0666 ; ajout de secubox-pilotage à la matrice CI backend-tests en Task 10 (X5)
- Ruling R20: l agent signale les sources en échec : `modele.Resultat` gagne `Echecs []string` (json `failed`, omitempty) posé quand une requête par préfixe a trouvé des valeurs mais qu au moins une source a échoué ; `Aplatir` inchangé ; le maître traite `failed` non vide, ou `err` accompagné de `params`, comme une passe dégradée (ajout seul, partiel=1, params gardés) — corrige T1 et T9 ensemble — coût si faux : un champ de protocole de plus
- Ruling R21: plafonds par box au maître : lignes d inventaire ≤ 2 × le plafond de paramètres de l agent (au-delà, les plus anciennes par releve_le sont purgées), événements ≤ 5000 par box (les plus anciens purgés) et ≤ 60 événements acceptés par minute et par box au canal (au-delà ignorés, compteur journalisé une fois par minute) ; GET /boxes/{x} borné par construction — coût si faux : historique tronqué pour une box très bavarde
- Ruling R22: la boucle de relève est démarrée par le premier lifespan et arrêtée seulement quand les DEUX applis se sont arrêtées (compteur) ; la Task 10 sert les deux applis avec lifespan="on" dans le même processus et la même boucle (pas le lanceur d autoload tel quel) — coût si faux : inventaire jamais relevé
- Ruling R23: entrée de menu en catégorie `mesh` (charte du hub : auth, wall, boot, mind, root, mesh) au lieu de `network` du brief — coût si faux : une catégorie à changer
- Ruling R24: secubox-pilotage livre son propre drop-in sysctl ip_nonlocal_bind (+ sysctl -w au postinst), pas de Depends sur secubox-annuaire — coût si faux : un fichier sysctl en double avec annuaire (même valeur)
- Ruling R25: journal d audit commun gardé (AGENTS.md) ; AppArmor en ajout seul (`a`) ; setfacl -P sur fichier régulier, nlink=1, propriétaire secubox seulement — coût si faux : relevé refusé (503) jusqu à 5 min après une rotation
- Ruling R26: sockets créées par deux unités .socket systemd (propriétaire, groupe, 0660), le lanceur sert sur les descripteurs reçus — supprime rm/umask/chgrp et l accaparement du chemin dans /run/secubox 1777 — coût si faux : adaptation du lanceur à LISTEN_FDS
- Ruling R27: l agent prend un compte propre `secubox-pilotage-agent` (co-installation maître+agent sur gk2) — coût si faux : un compte de plus
- Ruling R28: règles nft dans la base unifiée `inet filter` comme dans `inet secubox_filter`, avant la règle drop (après les bans), retirées à la purge ; absence de table journalisée — coût si faux : port ouvert seulement par la règle 10.0.0.0/8 générale, l identité reste filtrée par le canal
- Ruling R29: pas d entrée de menu propre (595-fleet de l annuaire existe) ; secubox-pilotage et secubox-pilotage-agent en `hors-arbre` de arbre.yaml (installés à la demande) jusqu à leur entrée dans les méta-paquets — coût si faux : une ligne à déplacer
- Ruling R30: `nginx -t` lancé hors du bac à sable par `systemd-run --wait --pipe --collect` (patron netmodes de RULES-CODE), l unité de l écouteur garde son durcissement ; exception RULES-CODE complétée (pas de profil AppArmor, nginx -t délégué) — coût si faux : une unité transitoire par passage
- Ruling R31: audit.py ouvre audit.log SANS O_CREAT (le journal est garanti par secubox-core et le postinst), AppArmor `a` gardé ; delegation.log (ouvert par secubox_core en "a") reçoit `w` comme dans les autres modules, faute de pouvoir changer secubox_core ici — coût si faux : un journal de délégation tronquable par ce service comme par les autres
- Ruling R32: banc T12 = gk2 (maître) + gk4 (RPi400, lite) + gk1 (MOCHAbin), maillés et joignables par clé ; MOCHAbin n°2 (192.168.42.161, Premier Pas inachevé) et RPi4 ajoutés quand le propriétaire les aura nommés et maillés ; mesure du budget ≤ 20 Mo sur gk4 (arm64) et sur gk5 (1 Go) quand le propriétaire ouvrira sa session ; chemin client wg-autoload (lgm-ebin injoignable) non validé en L1, noté — décision du propriétaire du 2026-10-29 (« tester sur la Mocha et le RPi4 ») — coût si faux : le chemin Auto-Load reste testé seulement en unitaire
- Ruling R33 (décision du propriétaire, 2026-10-29) : AUCUN test d agent sur box avant que l ensemble soit fini, interfaces comprises (L1 + L2 « Agir » + L5 « interface headless ») ; la Task 12 (banc, déploiement) est reportée après L5 ; L1 se termine par la Task 11 et la relecture finale de la branche, sans déploiement — coût si faux : retours terrain plus tardifs
- Ruling R34: avant la relecture finale, la branche est rebasée sur master ; collisions de version à lever : secubox-annuaire 0.16.1 et secubox-aggregator 0.5.1 existent déjà sur master (#3246, #3255) → la branche passe à 0.16.2 et 0.5.2 — coût si faux : paquets refusés par apt-publier (version déjà publiée)
- Ruling R35: le maître ne se pilote pas par son propre canal en L1 : l agent qui se découvre sur l adresse du maître (10.10.0.1 / 10.64.0.1) journalise une fois et attend, sans contacter le canal (corrige I3 ; R27 reste juste pour la séparation des comptes) — coût si faux : l inventaire de gk2 manque à la page Flotte en L1
- Ruling R36: I1 : le postinst de l agent ne crée plus /etc/secubox/pilotage (inutile : l env est /etc/secubox/pilotage-agent.env) ; R12 élargi : avant L2, tout fichier lu par l agent sous /etc/secubox (env, drapeau mains liées) doit être root:root et non inscriptible par d autres, sinon ignoré — coût si faux : un contrôle de plus au démarrage
- Ruling R37: I2 : l API autoload déclenche tunnel-sync (donc l export) après tout changement d abonnement, par le mécanisme « par fichier » existant ; l échéance « échu » est recalculée à chaque tunnel-sync et au moins une fois par heure (minuterie) — coût si faux : une minuterie de plus
- Ruling R38: I4 + R21 : une valeur liste n est plus rejetée au-delà de 4096 caractères : plafond par valeur porté à 64 Kio, au-delà la valeur est tronquée avec un marqueur explicite (jamais rejetée en bloc) ; un paramètre refusé ne rend plus toute la relève « partielle » s il est seul en cause ; le total d inventaire par box reste plafonné (10 000 lignes) — coût si faux : 64 Kio par valeur au pire
- Ruling R39: N1 corrigé AVANT la PR (dérogation à « une seule passe de correction » : Important, disque de gk2 à 91 %) : plafond d octets par box à l écriture, somme de length(valeur_json) ≤ 1 Mio (2 × 256 Kio + marge), contrôlé dans la branche dégradée, purge des plus anciennes lignes absentes de la passe comme pour LIGNES_MAX ; unité secubox-pilotage avec MemoryHigh/MemoryMax alignés sur les autres modules FastAPI — coût si faux : une box légitime à inventaire très bavard perd ses plus vieilles valeurs absentes
- Ruling R40: N2, N3, N4, N5 et M2, M6, M7, M12, M13, M15 reportés en L2 (Task 1 de L2 : verrou tunnel-sync/révocation, export même si wg échoue, ne pas relancer un wg-autoload arrêté volontairement, contrat maître→agent par fixtures) — coût si faux : défauts mineurs connus vivent jusqu à L2, rien n est déployé avant L5 (R33)
- Ruling R41 (décision du propriétaire, 2026-10-29) : Auto-Load et automesh RESTENT ; le pilotage s appuie dessus au lieu de les remplacer → la spec #3126 (L4, décision 11) est à réécrire en ce sens avant le plan L4 ; la page « Abonnements & profils » vit dans secubox-autoload, sans facturation (formule + échéance) — coût si faux : aucun, décision du propriétaire
